## 1. 請求書の印刷方法

1. AWS Billing and Cost Management コンソールを開く（左上の検索欄を利用）
2. 左側のメニューから「請求書」を選択
3. 右上「印刷」をクリックして印刷
4. 1ヶ月ごとの場合があるので、3を請求期間の分繰り返す

26年現在、AWSは新規アカウント作成者に100USドル分のクレジットを発行しており、対象のサービスであればこのクレジットから先に消費され、その分は請求されません。

## 2. インスタンスタイプの変更
EC2サーバーの性能向上のためや、コスト削減のためにインスタンスタイプを変更する方法です。
1. AWSコンソールのEC2＞「インスタンス」を開く
2. 現在利用しているインスタンスを選択し、右上「インスタンスの状態」＞「インスタンスを停止」を実行
	_誤って「終了」を押し削除しないよう注意！_
3. インスタンスが停止するまで待ち、停止したら「アクション」＞「インスタンスの設定」＞「インスタンスタイプの変更」に進む
4. 変更先のインスタンスタイプを選択し、確定する。
5. 再び「インスタンスの状態」＞「インスタンスを開始」から起動する。

#### インスタンスタイプについて
AWSにはたくさんインスタンスタイプがありますが、我々の用途（一般的なやつ）ではTシリーズが無難です。
T**2**, T**3**など番号は世代を表し、番号が大きい方が新しくて性能も良くて安いです。（AWSからすると、古い設備を維持するほうがコスト）
また次につく文字は規模を表します。t3.nano < t3.micro < t3.small < t3.medium ......　1つ段階が上がるごとに、値段は倍になります。値段が安いに越したことはないですが、ケチりすぎると性能が足りず、アクセスが多くなると落ちたり不安定になります。現時点（2026.2）では通常時はt3.micro, t3.smallが最低限でも必要だと思っています。本番は余裕を持たせてもいいかも。
他に気をつけるべきはCPUアーキテクチャで、x86_64系とARMが存在します。簡単に言えばCPUの命令と構造の違いで、t2やt3シリーズはx86_64、t4gなどはARMです。この2つには全く互換性がなく、ARMは比較的安くて新しいという魅力はありますが、ソフトウェアの互換性が保証できないのでおすすめしません。（もちろん自信があるなら止めないよ）
なお、x86_64にもCPUメーカーによる違い（IntelかAMDか）がありますが、気にする必要はありません。

#### 海外からのアクセスに、チャレンジ（ロボットではありません的なもの）を課す
1. Cloudflareのダッシュボードにアクセス
2. らくなびのドメインを選択し、メニューの「セキュリティ」＞「セキュリティ ルール」へ
3. 「ルールを作成」＞「カスタムルール」をクリック
4. 式を`(ip.src.country ne "JP")`として「マネージドチャレンジ」を課すよう設定

１日で500~1000件弱のリクエストを弾けました。

同様に「ログインページにチャレンジを課す」とか「Torをブロック」とかを適用しました。

Cloudflare無料プランは他にも有用な機能があり、調べて良さそうなら是非適用してみて下さい。

## 4. 🪏ドキュメントページ向けの画像を配信する
管理ページにドキュメントを閲覧できるページへのリンク（management/documents/）がありますが、ここではリポジトリの`docs/` フォルダ に存在するMarkDownファイルたちをHTMLに変換して表示しています。MarkDownでも画像が表示でき、ドキュメントに含まれていることがありますが、一般的なDjangoでの画像の扱いが異なるため、配信と表示にはひと工夫必要です。
具体的に現在の構成では、画像はローカルではmediaフォルダ、本番環境では自動でS3に保存されます。しかしドキュメントで使用する画像はもともと`docs/images` フォルダにあるため、手動でS3にコピーし、CDNで配信できるようにもしないといけません。

操作にはカスタムコマンドを使用します。
EC2上で、仮想環境に入り、

1. `python3 manage.py sync_docs_images --dry-run` を実行
	配信予定のアドレスに異常がないか確認しましょう。
2. `python3 manage.py sync_docs_images` を実行
	上手くいけば、画像がS3にコピーされ、CDNで配信されるようになります。
3. 動作確認
	画像が含まれるドキュメントを開き、画像が表示されるか確認しましょう。
この操作は、`docs/images` フォルダの画像を更新するたび行う必要があります。

## 5. 🪏セキュリティ強化設定（一括）
細かいセキュリティ用のヘッダや、CSRFトークン、CSP（ググれ）の設定などでセキュリティを強化しましょう。`.env` （開発用`.env.development` も含む）ファイルに
`DEPLOY_DONE = Flase` の記述があれば`Flase` を`True` にしてください。行自体がなければ追加して下さい。忘れず
`./scripts/apply_changes.sh` を実行するなり変更を適用しましょう。
これで、ある程度のセキュリティ機能を一括で有効に出来ます。これらの多くはserver_manual1で行ったSSL化が必須条件になるので、デプロイ完了後に作業しましょう。なお、この設定によって不具合が生じる場合は無効にしてOKです。
