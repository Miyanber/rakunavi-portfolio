### 手順

AWSのUI変更により、一部作業手順が前後する場合があります。

1. [AWS Console - Signup](https://signin.aws.amazon.com/signup?request_type=register) にアクセス

> Amazon Web Services (AWS) アカウントを初めて作成する場合は、このアカウントのすべての AWS サービスとリソースに対して完全なアクセス権限を持つシングルサインインアイデンティティで始めます。このアイデンティティは、AWS アカウントのルートユーザーと呼ばれます。AWS アカウント を作成するために使用したメールアドレスとパスワードは、ルートユーザーとしてサインインするために使用する認証情報です。

## 2. Amazon EC2 インスタンスの作成

Amazon EC2 は、AWS が提供する仮想サーバー構築サービスです。"Elastic Compute Cloud" の略で、クラウド上で自由にサーバーを構築・利用できます。EC2 を使うことで、物理サーバーの購入や設置の手間を省き、必要な時に必要な分だけサーバーリソースを確保できます。

また、**EC2 インスタンス** は、**レンタルできる「ネット上のパソコン」** を表すと思ってください。世界中のどこからでもアクセスでき、このパソコン上で Web アプリケーションを運営（ホスト）することができます。**インスタンス = サーバー**と捉えてもらって構いません。

### 手順 1 - VPC ネットワークの確認

VPC ネットワークに関する詳細な説明は省きます。興味がある方はご自分で調べてみましょう。

1. AWS マネジメントコンソールにログイン
2. **右上に表示されているリージョンを「アジアパシフィック (東京)」に変更する**
   - **この手順は忘れがちなので注意すること！** 
3. 左上の検索バーに「VPC」と入力し、VPC コンソール (独立したクラウドリソース) を開く
4. 左のメニューバーから「仮想プライベートクラウド」 > 「お使いの VPC」を選択
5. デフォルトで 1 個の VPC が作成されていることを確認する。
6. 万が一 VPC が一個も見当たらない場合は、右上の「アクション」から「デフォルト VPC を作成」を選択し、デフォルトの VPC を作成しておく。

### 手順 2 - EC2 インスタンスの作成

1. AWS マネジメントコンソールにログイン
2. **右上に表示されているリージョンを「アジアパシフィック (東京)」に変更する**
   - **この手順は忘れがちなので注意すること！** 
3. 左上の検索バーに「EC2」と入力し、Amazon EC2 コンソール (クラウド内の仮想サーバー) を開く
4. 左のメニューバーから「インスタンス」 > 「インスタンス」を選択
5. 右上の「インスタンスを起動」をクリック
6. 名前は「RakuNavi2025」のように入力（正味分かれば何でも良い）
7. アプリケーションおよび OS イメージ (Amazon マシンイメージ) は、選択肢より「Ubuntu」を選択し、Amazon マシンイメージが「Ubuntu Server 24.04 LTS (HVM), SSD Volume Type（無料利用枠の対象）」であることを確認 <br>※「24.04」の部分は Ubuntu のバージョンを表しているため、上記のバージョンと異なる可能性があります。その場合は、**「無料利用枠の対象」という表記があることを確認**して下さい。
8. インスタンスタイプが「t3.micro（無料利用枠の対象）」であることを確認
9.  キーペアは「新しいキーペアを作成」をクリックすると「キーペアを作成」というポップアップが現れる。キーペア名は名前とタグと同様に「RakuNavi2025」のように入力する。キーペアのタイプは「ED25519」を選択し、プライベートキーファイル形式は「.pem」を選択して、「キーペアを作成」をクリックする。pem ファイル（以下、鍵ファイルと呼びます）がダウンロードされるので、任意の場所に保存する。※ 鍵ファイルは、後でインスタンスに接続する際に利用します。
10. ネットワーク設定では、ファイアウォール (セキュリティグループ) で「セキュリティグループを作成」を選択し、「からの SSH トラフィックを許可」で「自分の IP」を選択する。「からの SSH トラフィックを許可」「インターネットからの HTTPS トラフィックを許可」「インターネットからの HTTP トラフィックを許可」には全てチェックを入れる。
11. ストレージを設定では、「1x 8 GiB gp3 ルートボリューム」になっていることを確認
<!-- 12. セキュリティグループで以下を許可：
   - SSH（ポート 22）
   - HTTP（ポート 80）
   - HTTPS（ポート 443） -->
1.  ここまで入力ができたら、間違いがないか再度確認をして、一番下の「インスタンスを起動」をクリック

これでインスタンスが起動できました。冒頭にも書きましたが、これを「**AWS EC2 インスタンス**」と呼びます。これがいわゆる「**サーバー**」にあたります。インスタンスは AWS のリージョン内のどこかにあるコンピューターを借りているイメージですので、**インスタンス=コンピューター**と考えていただけると分かりやすいかと思います。以下、「サーバー上で」等と言われたら、このインスタンスのことを指すと考えてください。

###### 補足
T3シリーズを利用する場合、意図しない課金を避けるため、EC2>「インスタンス」から利用中のインスタンスを選択し、
「アクション」＞「インスタンスの設定」＞「クレジット仕様の変更」で無制限モードを解除して下さい。
無制限モードでは、CPUクレジットを使い果たしてもどんどん自動課金してCPUを動かし続けます。

## 3. Elastic IP アドレスの割り当て

先ほど作成したインスタンスはコンピューターなので、IP アドレスを持ちます。AWS EC2 インスタンスでは、この IP アドレスを「**パブリック IP アドレス**」と呼びます。

しかし、このパブリック IP アドレスは、インスタンスを停止→再起動するたびに変わってしまいます。インスタンスを停止すると、動的パブリック IP は解放される仕様のためです。これを避けるためには「**Elastic IP（固定IP）**」を取得し、インスタンスに割り当てる（関連付ける）必要があります。
※「 IP を開放する」とは、簡単に言うと IP を削除するという意味です。

### 手順 1 - Elastic IP を割り振る

1. AWS マネジメントコンソールにログイン
2. **右上に表示されているリージョンを「アジアパシフィック (東京)」に変更する**
   - **この手順は忘れがちなので注意すること！** 
3. 左上の検索バーに「EC2」と入力し、Amazon EC2 コンソール (クラウド内の仮想サーバー) を開く
4. 左のメニューバーから「ネットワーク ＆ セキュリティ」 > 「Elastic IP」を選択
5. 右上の「Elastic IP アドレスを割り振る」を選択
6. デフォルト設定のまま、画面下部の「割り振る」をクリック
7. これで Elastic IP を割り振ることができました。

### 手順 2 - Elastic IP アドレスを EC2 インスタンスに関連付ける

1. Elastic IP のコンソールを開く（手順 1 の後であれば自動的に開かれています）
2. 先ほど割り振った Elastic IP アドレスをクリック
3. 右上に表示されている「Elastic IP アドレスを関連付ける」を選択する。すると、「Elastic IP アドレスを関連付ける」という画面が開きます。
4. リソースタイプは「インスタンス」を選択していることを確認
5. インスタンスは先ほど起動したインスタンス（RakuNavi20XX）を選択
6. プライベート IP アドレスは空欄のまま
7. 再関連付けは、一応許可しておく
8. 以上で内容を確認して「関連付ける」をクリック
9. これで Elastic IP をインスタンスに割り振ることができました。

ここで割り振った Elastic IP アドレスは後で利用するので、メモしておくことをお勧めします。

## 4. インスタンスへの接続

先ほどインスタンスの作成を行いました。今度はこのインスタンス=コンピューターに接続していきます。これを「EC2 インスタンスにログインする」と言います。

※ **Windows の方へ。** サーバーの OS は Linux になるため、**WSL (Windows Subsystem for Linux) 上でコマンドを実行することをお勧めします。** ここでは基本的に Linux / MacOS のコマンドしか紹介しません。WSL のディストリビューションは、サーバーに合わせる為 Ubuntu を利用して下さい。なお、鍵ファイルも WSL 上に移動する必要があります。

※ Windows の方で、万が一ハードウェアの関係で WSL を利用できない場合、申し訳ありませんが、ローカルでコマンドを実行する際は PowerShell での書き方に自分で変更して下さい。ちなみに ChatGPT に頼めば Linux 用のコマンドでも PowerShell で動くようにしてくれます。活用しましょう。

🪏自分のPCでLinux（Ubuntuなど）利用している人。素晴らしい。

### ローカル端末からの接続

### 手順

1. EC2 インスタンスの作成時にダウンロードした鍵ファイル（RakuNavi20XX.pem）のパスをメモ（エクスプローラ等からコピー可能）
2. インスタンスに関連づけた Elastic IP のアドレス（割り振られた IPv4 アドレス）をメモ
3. ターミナルを開き、OSに応じて以下の例のようにコマンドを入力する
   - `鍵ファイルのパス`や`RakuNavi20XX.pem`, `Elastic IP アドレス`の部分は適宜書き換えること。
   - 一回メモ帳などに書き直してからターミナルに貼り付けてもOK
   - 初心者は一行ずつ実行することをお勧めします。

#### コマンド

```bash
# 🪏
# フォルダ作成
# Ubuntuなら元々あるはずなので、おそらくこの作成コマンドは不要。mvコマンドで移動できなければ試してね。
mkdir ~/.ssh

# 鍵ファイルを移動
mv 鍵ファイルのパス ~/.ssh
# 鍵ファイルの権限を設定（読み込みのみに制限）
chmod 400 ~/.ssh/RakuNavi20XX.pem
# SSH接続
ssh -i ~/.ssh/RakuNavi20XX.pem ubuntu@"Elastic IP アドレス"
```

#### コマンド実行例（宮崎の WSL）

宮崎の場合は鍵ファイルを WSL 上の `~/rakunavi/RakuNavi2025.pem`に保存していました。

```bash
mkdir ~/.ssh
mv ~/rakunavi/RakuNavi2025.pem ~/.ssh
chmod 400 ~/.ssh/RakuNavi2025.pem
ssh -i ~/.ssh/RakuNavi2025.pem ubuntu@203.0.113.10
# ssh -i ~/.ssh/Rakunavi2025.pem ubuntu@203.0.113.11
```

#### Daphne, Nginx の設定

アプリケーションサーバーと Web サーバーの設定を行います。アプリケーションサーバーとか Webサーバーとはなんぞやという方は、 [解説 - Django + Nginx + Daphne 構成](#解説---django--nginx--daphne-構成) を一読してください。

🪏Ubuntuを含むLinuxでは、起動時からバックグラウンドで動く処理をサービス(service)とかデーモン(daemon)と呼びます。これからDaphneのサービスを作成して有効化していきます。

まずは `daphne.service` を作成します。インスタンス上で以下のコマンドを実行して下さい。実行すると、`GNU nano 7.2` という文字が左上に表示されるようになると思います。

```bash
# インスタンス上で実行
sudo nano /etc/systemd/system/daphne.service
```

これは nano コマンドと呼ばれ、Linux 用のテキストエディタを開くコマンドになります。インスタンス上には GUI が存在しないため、ファイルの変更などは基本的に CLI で行う必要があります。その一つの方法として nano コマンドがあるのです。ここから先しばらくは、このテキストエディタ上でファイルを編集し、保存するという流れになります。

次に、開いたテキストエディタに以下の内容をコピペ（マウス右クリックでペースト可）します。

```conf
[Unit]
Description=Daphne ASGI Service
After=network.target

[Service]
User=ubuntu
Group=www-data
WorkingDirectory=/home/ubuntu/RakuNavi
ExecStart=/home/ubuntu/RakuNavi/.venv/bin/daphne \
  -b 127.0.0.1 \
  -p 8001 \
  rakunavi.asgi:application

Restart=always
RestartSec=3
CPUQuota=80%
KillSignal=SIGQUIT
Type=simple

[Install]
WantedBy=multi-user.target
```

貼り付けたらエディタを終了 (Exit) しましょう。エディタの操作については、エディタ画面下部にある、`^G Help  ^O Write Out  ^W Where Is ...` を参考にして下さい。`^G` や `^O` のように、`^` (キャレット / ハット) で始まるキーは、`control` (`Ctrl`) キーを押しながらそのキーを押すことを意味します。今回の `Exit` ではキーが `^X` と書かれているので、`control` (`Ctrl`) キーを押しながら `X` キーを押せばよいということになります。この際ファイルに変更を加えた場合は `Save modified buffer?` と聞かれるので、` Y` (Yes) を押します。特に `^` が表記されていない場合は、単にそのキーだけ押せばよいです。後は `Enter` を押せば元のターミナルに戻ります。


次に、サーバーへのリクエストを Django アプリケーションに中継する設定を行います。以下のコマンドを実行して下さい。

```bash
# インスタンス上で実行
sudo nano /etc/nginx/sites-available/rakunavi
```

以下の内容を貼り付けて、ファイルを保存して下さい。
**※ `"Elastic IP アドレスの値"` は適宜変更すること。**

```.conf
upstream daphne {
    server 127.0.0.1:8001;
}

server {
    server_name "Elastic IP アドレスの値";

    # =========================
    # WebSocket（明示的に許可）
    # =========================
    location ^~ /ws/ {
        proxy_pass http://daphne;

        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # =========================
    # WebSocket っぽい不正パス遮断
    # =========================
    location ~* ^/(ws-|wsfapi|ws/[^/]+@) {
        return 444;
    }

    # =========================
    # 通常 HTTP（Django）
    # =========================
    location / {
        proxy_pass http://daphne;

        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # ★ HTTP では Upgrade ヘッダを渡さない
        proxy_set_header Upgrade "";
        proxy_set_header Connection "";

        proxy_redirect off;
    }

    # =========================
    # Static / Media
    # =========================
    location /static {
        alias /home/ubuntu/RakuNavi/staticfiles/;
        access_log off;
    }

    location /media {
        alias /home/ubuntu/myproject/media/;
        expires 7d;
        add_header Cache-Control "public";
    }

}
```

次に、Nginx の設定を有効にして、再起動します。以下のコマンドを実行して下さい。

```bash
# Nginx の設定を有効化
sudo ln -sfv /etc/nginx/sites-available/rakunavi /etc/nginx/sites-enabled/rakunavi
# Nginx を再起動
sudo systemctl restart nginx.service
# Nginx が静的ファイルを読み込むための権限
chmod o+rx ~
```

これで、サーバーがリクエストを受け取り、ページを表示できるようになりました。

### 解説 - Django + Nginx + Daphne 構成

ここから Web サーバー, アプリケーションサーバーの設定に入ります。Web サーバーやアプリケーションサーバーに関する知識がある場合や、急いで作業している場合は読み飛ばしてもらって結構です。

#### 用語

| コンポーネント  | 役割           | 例                |
|---------------|---------------|-----------------|
| Nginx         | Web サーバー | 玄関口。リバースプロキシとも呼ばれます。静的ファイルなら自分で処理、それ以外はアプリケーションサーバに渡す。 |
| Daphne      | アプリケーションサーバー  | WSGI / ASGI アプリケーションサーバ。Django のコードを実行して HTML などのレスポンスを生成。|
| Django        | Webアプリ本体   | アプリ本体。URL ルーティング、DB処理、テンプレート描画など全部やってくれる。レスポンスの生成を行う。  |


#### クライアントからレスポンスが返るまでの流れ（Django + Nginx + Daphne 構成の場合）

1. クライアント（ユーザーのブラウザ）からリクエストが飛ぶ
   - 例：https://rakunavi.example.com/exhibition/class 
2. Nginx がまず受け取る（リバースプロキシ）
   - 静的ファイル（CSS, JS, 画像など）ならそのままNginxが返す。
   - それ以外のリクエスト（動的ページなど）は、**Daphne に転送する**。
3. Daphne が Django のコードを実行してレスポンスを生成
   - URL ルーティングやデータベースへのアクセスなどを処理。
   - 必要な HTML をテンプレートエンジンで生成するなどして、最終的なレスポンスを作る。
4. Daphne が Nginx にレスポンスを返す
5. Nginx がクライアントにレスポンスを返す

ざっくりいうと、 Nginx → Daphne → Django というイメージです。

### 覚えるべきコマンド

ここから先、自分でできるようにならなければならない作業です。

#### Django のログの確認

```bash
cat /var/log/rakunavi/django.log
```

らくなび本番環境では Django のログを `/var/log/rakunavi/django.log` に出力しています。エラーの内容を細かく確認したい場合は、こちらのログを確認しましょう。

#### Daphne のログの確認

```bash
sudo journalctl -u daphne.service
# 直近50件のみ表示
sudo journalctl -u daphne.service -n 50
# その他、任意の時間以降のログ取得など
sudo journalctl -u daphne.service --since '2026-01-27 00:00'
```

Daphne のログを確認できます。Django のログだけでエラーを解決できなかった場合は、こちらのログも確認してみると良いでしょう。

#### Nginx のログの確認

```bash
sudo journalctl -u nginx.service
```

Nginx のログを確認できます。Daphne のログだけでエラーを解決できなかった場合は、こちらのログも確認してみると良いでしょう。

#### Daphne, Nginx の再起動

```bash
# 設定を再読み込み
sudo systemctl daemon-reload
sudo systemctl restart daphne
sudo systemctl restart nginx
```

Daphne, Nginx を再起動します。**Django のコードに変更を加えた場合、このコマンドを実行することで、コードの変更を反映できます。** ローカルでの開発時でも、コードに変更を加えたら `runserver` し直していたと思います。これと同じイメージを持つと分かりやすいでしょう。なお、Nginx の再起動は不要なことが多いです。ただし、 `.env` に変更を加えた際は、Nginx も再起動しないと反映されません。変更が反映されていないと思う場合はサボらず Nginx も再起動しましょう。

🪏井﨑は面倒くさがりなので、既に scripts/apply_changes.sh にこれを一度に行うスクリプトを作りました。
よってコード変更を反映したいときは、
```bash
./scripts/apply_changes.sh
```
のように実行してもいいかも知れません。

## 5. Cloudflare Register でドメイン取得・適用

### 手順 1 - Cloudflare アカウント作成

基本的には AWS アカウントの作成と似ているため、ここでは詳細な説明は省きます。頑張って作成して下さい。なお、AWS アカウントと同じくクレジットカード情報が必要です。

Cloudflare の公式ページは[こちら](https://www.cloudflare.com/ja-jp/)です。なお、上級者で他のドメインサービスの扱いに慣れている場合は、そちらを使用してもらっても構いません（例えばお名前ドットコム等）。

### 手順 2 - ドメイン取得

#### ドメイン取得費用に関して補足

ドメイン取得の際にかかる費用としては、①ドメイン取得にかかる費用と②ドメインの更新にかかる費用（毎年更新）があり、それぞれ TLD (.com, .net, .org など) に応じて異なります。例えば `rakunavi2025.com` は①②ともに 10.44 ドル、`rakunavi2025.net` は①②ともに 11.84 ドルです（2025年7月12日時点。ドメイン購入時に可能）。**らくなびの予算案ではドメインの取得料金を 11.84 ドルとして計算しているため、これよりも高い取得・更新費用がかかる TLD のドメインを取得するのは可能な限り避けてください。**

🪏円安を意識しますね―ｗ

#### 手順

1. Cloudflare ダッシュボードにアクセス
2. 左側のメニューから Domain Registration -> Register Domains を開く
3. ドメインを購入（rakunavi2025.com など）
   - **ドメインの価格に注意すること！**
   - 情報

以上でドメインが取得できます。ドメイン購入の際は、個人情報の入力が求められます。一般にドメインの登録時には登録者の個人情報が必要ですが、多くのレジストリサービスでは WHOIS 代行サービスが存在し、基本的に公開されることはありません。なお、 Cloudflare では WHOIS 代行に相当するものとして WHOIS redaction というサービスが用意されています。

### 手順 3 - DNS レコード (A レコード) の作成

#### ホストゾーンに関して

ホストゾーンとは、簡単に言うと、特定のドメインに関する設定を集めた場所のことです。ここに DNS レコードというやつが入ります。普通はドメインを取得後 AWS Route 53 でホストゾーンを作成するのですが、今回は Cloudflare 上で DNS 管理が可能なため、その必要はありません。

#### DNS レコードを追加する理由

Elastic IP アドレスとドメイン名を紐づけるためです。これもまた「情報Ⅰ」で学習するのですが、我々が Web サイトにアクセスする際、例えば "https://miyanber.com" にアクセスする場合、DNS サーバーというやつに "miyanber.com" というドメインの IP アドレスを問い合わせて、取得した IP アドレスの値で Web サイトにアクセスするという手順を踏んでいます。この「ドメインの IP アドレスを問い合わせ」るという作業を可能にするのがこの DNS レコードになります。

#### 手順

1. Cloudflare ダッシュボードにアクセス
2. Account Home をクリック
3. 取得したドメインを選択
4. 左側のメニューから DNS をクリック
5. "Add record" をクリックして、A レコードを追加する
   1. Type は A を選択。これで「IPv4アドレスに向ける」という意味になります。
   2. Name は @ と入力。ルートドメインを指します。
   3. IPv4 address にインスタンスの Elastic IP アドレスの値を入力。
   4. Proxy status はとりあえず Proxied にしておく。
   5. 「Save」をクリックして保存。

以上で DNS レコードが追加されました。

### 手順 4 - ALLOWED_HOSTS の値を変更

ALLOWED_HOSTS にドメイン名（ホスト名）を追加しないと、Django はサーバーを起動してくれません。

#### やり方 1

1. インスタンスに SSH 接続して下さい。やり方が分からない場合は前のセクションを振り返って下さい。
2. nano コマンドで、.env ファイルを開いてください。
   - `sudo nano ./RakuNavi/.env` とかのコマンドでいけると思います。`sudo` を忘れないようにしましょう。
   - 上のコマンドで上手くいかない場合は、引数無しで `cd` コマンドを実行してから上のコマンドを実行するといけると思います。
3. ALLOWED_HOSTS の所に、カンマ (,) 区切りで Elastic IP アドレスの後に取得したドメイン名を記述します。

#### やり方 2

1. ローカルの `.env` を開いて、ALLOWED_HOSTS の所にカンマ (,) 区切りで Elastic IP アドレスの後に取得したドメイン名を記述する。
2. scp コマンドで `.env` をインスタンス上にアップロードする。

やり方 1, 2 のどちらを利用してもらっても構いませんが、どちらかにやり方は統一しておくことをお勧めします。

各種コマンドの使い方に関しては、`/docs` 直下の `aws_useful_commands.md` にまとめています。そちらも参考にして下さい。

以上で完了です。

## 6. SSL 化

そもそも SSL 化とはなんやといいますと、Web サイトの通信を暗号化することを指します。いわゆる HTTPS 接続ができるようにします。「この接続は保護されています」とブラウザ上に出るやつですね。
SSL 化をすることで、Webサイトの通信内容が盗聴されることを防ぎ、セキュリティを向上させることができます。詳細なメリットについては是非自分で調べてみましょう。

### 手順 1 - SSL 化

[certbot](https://certbot.eff.org/instructions?ws=nginx&os=pip) というものを利用します。リンクのページに書いてあることをそのまま実行すれば SSL 化できます。簡単ですね。とはいえ、分からないところもあるかと思いますのでこちらで解説します。らくなび専用にまとめてあります。

まず、インスタンスに SSH 接続します。パッとできますか？ 覚えていないよという方は、最初の方に「覚えるべきコマンド - ssh コマンド」みたいなのがあると思いますので、そちらを参考にして下さい。何回も振り返って、知識を自分のものにしていきましょう！

次に、以下のコマンドを実行します。

```bash
sudo apt update
sudo apt install python3 python3-dev python3-venv libaugeas-dev gcc
sudo python3 -m venv /opt/certbot/
sudo /opt/certbot/bin/pip install --upgrade pip
sudo /opt/certbot/bin/pip install certbot certbot-nginx
sudo ln -s /opt/certbot/bin/certbot /usr/bin/certbot
```

これはただの初期設定になります。次に、以下のコマンドを実行して、certbot がドメイン名に正しく SSL 設定を行えるように、`/etc/nginx/sites-available/rakunavi` の設定を変更します。ファイルを編集するコマンド、何でしたか？できれば振り返ってみましょう。

```bash
sudo nano /etc/nginx/sites-available/rakunavi
```

開いたテキストエディタで、2 行目の記述を以下のように変更する。こうすることで、certbot が設定ファイルを発見できるようになります。

```diff
server {
-  server_name "Elastic IP の値";
+  server_name rakunavi.example.com;

   location / {
```

それでは、certbot に SSL 化を行ってもらいましょう。以下のコマンドを実行して下さい。

```bash
sudo certbot --nginx -d rakunavi.example.com
```

色々聞かれるので、指示に従ってください。英語がどうしても分からない場合は、DeepL 先生に頼んで翻訳してもらいましょう。
（🪏頑張って英語得意になろうね）

もし赤文字が出て、何かしら "failed" と表示された場合は、ドメイン名を間違えているか、この前の DNS レコードの A レコードが正しく設定されていない可能性があります。スペルミスがないかチェックしましょう。

### 手順 2 - 動作確認

これで SSL 化が完了しました。https://ドメイン名 でアクセスできるようになっているはずです。一度アクセスしてみましょう。

🪏注意！　Cloudflareの処理か何かに時間がかかっているためか、ブラウザでアクセスするとSSLバージョンなどのエラーが出ているかも知れません。（私が遭遇しました）
その時は一旦時間を置いてみましょう。

#### トラブルシューティング

- ドメイン名からアクセスできない
  - ドメイン名入力時に TLD (.com 等) を入れ忘れていないかチェックして下さい。
  - 次に Elastic IP アドレスでアクセスできるか確認しましょう。万が一それでもできない場合は、そもそも Daphne 等の設定でミスがある可能性があります。
  - Elastic IP アドレスではアクセスできる場合、DNS レコードの設定をミスっている可能性があります。改めてレコードの種類・アドレス・名前にミスがないか確認しましょう。
- Welcome to Nginx! と表示された場合
  - Nginx の設定がうまくいっていないです。きちんと `/etc/nginx/sites-available/rakunavi` の内容 (server_name) を修正してから `sudo certbot --nginx -d rakunavi.example.com` を実行しましたか？
  - `sudo cat /etc/nginx/sites-available/rakunavi` を実行してファイルの中身を確認し、"# managed by Certbot" という記述が何かしらあるかを確認して下さい。もし存在しない場合は、certbot が設定ファイルを上手く見つけられていないです。恐らく `/etc/nginx/sites-available/default` に間違って設定ファイルが書かれている可能性があります。その場合は、`sudo rm /etc/nginx/sites-enabled/default` でいったんそのファイルを削除し、`/etc/nginx/sites-available/rakunavi` の内容 (server_name) を正しく修正してから、`sudo certbot --nginx -d rakunavi.example.com` を実行しなおしてください。

### 手順 3 - SSL 証明書の定期更新

次に、定期的に SSL 証明書を更新させるため、以下のコマンドを実行します。

```bash
echo "0 0,12 * * * root /opt/certbot/bin/python -c 'import random; import time; time.sleep(random.random() * 3600)' && sudo certbot renew -q" | sudo tee -a /etc/crontab > /dev/null
```

## 7. S3 バケットの設定（静的ファイル用）

AWS S3 ( Simple Storage Service ) のバケットを作成します。

### S3 とは

いわゆるオブジェクトストレージサービスというものです。静的なファイル（画像ファイルや CSS ファイル、JS ファイル等）はこの S3 に保存・配信することが多いです。これにはサーバー（インスタンス）の負荷を軽減するという目的があります。

### 手順 1 - バケットの作成

1. AWS **S3** コンソールを開く
2. **右上に表示されているリージョンを「アジアパシフィック (東京)」に変更する**
   - **この手順は忘れがちなので注意すること！** 
3. 「バケットを作成」をクリックし、バケットを作成
   1. バケットタイプ：汎用
   2. バケット名：**`cdn.ドメイン名` ← 形式厳守！** 例: `cdn.rakunavi.example.com`
   3. そのほかはデフォルトのまま「バケットを作成」をクリック

これでバケットが作成されました。なお、**バケット名をミスると CDN の設定で詰む**ので注意して下さい。

### 手順 2 - IAM ユーザーの作成

S3 にアクセスするためのアクセスキーとシークレットキーを作成します。

1. AWS コンソールにアクセス
2. IAW ダッシュボードに移動（上の検索バーで IAM と検索）
3. 左側のメニューから アクセス管理 -> ユーザー をクリック
4. 「ユーザーの作成」をクリック
5. ユーザー名は rakunavi2025-uploader 等
6. 他はデフォルトのまま「次へ」
7. 許可のオプションは「ポリシーを直接アタッチする」を選択
8. 許可ポリシーは「ポリシーの作成」をクリックする（**新規タブで開きます**）
   1. ポリシーエディタで「JSON」を選択し、以下の [S3ReadWriteRakuNaviBucketOnly ポリシー](#s3readwriterakunavibucketonly-ポリシー) を貼り付ける
   2. 他はデフォルトのまま「次へ」
   3. ポリシー名は S3ReadWriteRakuNaviBucketOnly と入力して作成
   4. 「ユーザーの作成」タブに戻る
9. 許可ポリシーの所をリロードする（右にリロードボタンがあります）
10. 先ほど作成した S3ReadWriteRakuNaviBucketOnly ポリシーにチェックを入れる
11. 「次へ」をクリック
12. 軽く内容を確認し、「ユーザーの作成」をクリック

これでユーザーが作成されました。

#### S3ReadWriteRakuNaviBucketOnly ポリシー

- **※ `バケット名` は適宜変更すること！**

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:GetObject",
                "s3:ListBucket",
                "s3:PutObject"
            ],
            "Resource": "arn:aws:s3:::バケット名/*"
        }
    ]
}
```

### 手順 4 - アクセスキーの取得

### 手順 5 - `.env` の編集

作成したバケットの情報を、インスタンス上の `.env` に記述していきます。なお、インスタンス上で nano コマンドを実行して編集するか、ローカル上の `.env` に下書きして scp コマンドでアップロードするかはお任せします。※ ローカル上の `.env` に下書きする場合、ALLOWED_HOST の値が本番環境のものと相違ないか確認して下さい。

インスタンス上の `.env` 内の AWS S3 の所を以下のように変更して下さい。やり方は前述したように、好きにして下さい。「アクセスキー」「シークレットアクセスキー」については、先ほど取得した値を利用して下さい。S3「バケット名」の変更もお忘れなく。AWS_S3_REGION_NAME については、言われた通り東京リージョンを使用していれば、このままで OK です。

```python
# AWS S3
AWS_ACCESS_KEY_ID='アクセスキー'
AWS_SECRET_ACCESS_KEY='シークレットアクセスキー'
AWS_STORAGE_BUCKET_NAME='バケット名'
AWS_S3_REGION_NAME='ap-northeast-1'
```

### 手順 6 - 静的ファイルの配信

いよいよバケットにデータを入れていきます。

1. インスタンスに SSH 接続する
2. 以下のコマンドを実行

```bash
# インスタンス上で実行
cd ./RakuNavi
source .venv/bin/activate
python manage.py collectstatic --no-input
```

エラー無く実行できれば OK です。

#### トラブルシューティング

- collectstatic で 403 エラーが出る
  - 宮崎も苦労しました。しかし、マニュアル通りに書けばエラーは出ないように作りました！
  - バケット名の後にスペースが入ってないか確認しましょう。
  - その他、スペルミスがないか確認しましょう。値の変更は基本コピペでやりましょう。
  - 🪏「S3なんちゃらDeleteObject云々、、」とエラーが出る場合、IAMユーザーの権限にDeleteObjectを与えたら（設定画面の他はデフォルトで進む）上手くいきました。（正しいかは知らぬ）
 

### 手順 7 - CORS 設定

CORS（コルス; オリジン間リソース共有）の設定をします。
作成したバケットのページを開いて、「アクセス許可」タブの最下部にある「Cross-Origin Resource Sharing (CORS)」を編集し、以下のコードをコピペしてください。※ `ドメイン名` は適宜変更すること。

```json
[
	{
		"AllowedHeaders": ["*"],
		"AllowedMethods": ["GET", "PUT"],
		"AllowedOrigins": ["https://ドメイン名"],
		"ExposeHeaders": [],
		"MaxAgeSeconds": 86400
	}
]
```

これで、CDN にらくなびからアクセスできるようになりました。なお、`"MaxAgeSeconds": 86400` に関しては、プリフライトリクエストのキャッシュ保持時間です。要するに CORS 設定のキャッシュ保持期間ととらえても良いと思います。詳細はご自分で調べてみてください。

## 8. Cloudflare CDN 設定

CDN の設定をします。CDN（コンテンツ・デリバリー・ネットワーク）とは、Webサイトのコンテンツを世界中に分散配置されたサーバーにキャッシュし、ユーザーに最も近いサーバーからコンテンツを配信することで、表示速度の向上やサーバーへの負荷軽減を実現する仕組みです。

### 手順 1 - CNAME レコードの追加

1. Cloudflare のダッシュボードを開く
2. 左側のメニューから Account Home をクリック
3. 取得したドメインを選択
4. 左側のメニューから DNS をクリック
5. 「Add record」で CNAME レコードを追加する
   1. Type : CNAME
   2. Name : cdn と入力
   3. Target : バケット名.s3.ap-northeast-1.amazonaws.com と入力 ※バケット名は適宜変更すること
   4. 「Save」をクリックして保存

以上で完了です。

### 手順 2 - CDN_DOMAIN の変更

インスタンス上の `.env` 内の `CDN_DOMAIN` を以下のように変更します。

```python
CDN_DOMAIN='cdn.ドメイン名'
```

やり方は好きにして下さい。インスタンス上で nano コマンド or ローカルで変更し scp コマンドでアップロード。ただしどちらかに統一して下さい。

### 手順 3 - 動作確認

https://ドメイン名 にアクセスして、CSS がロードされた状態のらくなびが表示されれば成功です。お疲れ様でした。
