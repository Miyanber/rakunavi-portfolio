# Git 基本事項

## 注意事項

- ブランチを移動して作業する際は、今いるブランチが最新であるか必ず確認する
- 作業する際は、基本的に自分専用のブランチを作成して行う
  - ブランチ名は実装内容（AutoScrollGallery等）
- ブランチを作成したタイミングでプルリクエストを出しておく
- プルリクを経て完成したものは、その年度専用のブランチ（2025等）にマージする。※mainにはマージしない
- 以上の流れをまとめると以下のようになる
1. 作業用ブランチを作成する。
2. プルリクエストを出す。この際作業する内容の概要をプルリクに書いておく。
3. ある程度機能が完成したら、他の開発者にコードレビューをしてもらう
4. 問題点があれば修正する
5. 他の開発者の同意を得たら、適切なブランチにマージする（大抵は年度用ブランチにマージする）
6. 適宜コンフリクトは解決する。この際不明な点があれば遠慮なく他の開発者に質問する。

## 用語確認

- origin = リモートリポジトリを指す、変数的なもの

### pull コマンド

fetch と merge をひとまとめにしたもの。コードを最新の状態に更新したい時はこのコマンドを利用する。ただし、コンフリクトが起きた後の処理が面倒なので注意。一応 fetch + merge の方が安全。

```bash
git pull リモート名 リモートブランチ名

# 引数無し->リモート名：origin,ブランチ名：上流ブランチ(?)
git pull
```

### fetch コマンド

ローカルリポジトリ内に存在する、リモートリポジトリの情報を更新する。ローカルリポジトリにはまだ更新は反映されない。リモート名は`origin`を指定することが多い。

```bash
git fetch リモート名 リモートブランチ名

# リモートブランチ名を指定しない場合は、リモートにあるすべてのブランチに対応するローカルブランチを更新
git fetch リモート名

# リモート名無し -> リモート名は自動的に origin になる
git fetch
```


### merge コマンド

現在いるブランチに、指定したブランチを統合する。コンフリクトが起きることがあるので注意。

```bash
git merge ブランチ名

# 引数なし -> 上流ブランチ（？）
# 理解できていなければ省略しないこと
git merge
```

### ブランチの削除

```bash
# ローカルのブランチを削除する場合
git branch -d ローカルブランチ名

# リモートのブランチを削除する場合
git push origin --delete リモートブランチ名
```

### 特定のコミットまで戻す

#### reset コマンド

指定したコミットの所まで戻す。コミットを戻したという履歴すら残らないが、その分コミット履歴が綺麗になる。利用する際は他の開発者全員の了承を得る事。共同開発者のGitに削除したコミットが残っている場合、共同開発者がプッシュした際にコミットが再送されてしまう為注意。←？

```bash
git reset --hard コミットハッシュ

# これでリモートブランチに同期
git push -f origin リモートブランチ名
```

#### revert コマンド

特定のコミットを取り消す。コミット履歴には残る。引数にはコミットハッシュ（fdf95405e0a4994e82eb916cb9cde4e84b389f3d のような一意のID）を指定する。

```bash
git revert コミットハッシュ
```
